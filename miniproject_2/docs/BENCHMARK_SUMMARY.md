## 1.1 Optimal Configuration vs Resolution Analysis

### Summary Table

| Resolution | Optimal Chunk | Optimal P | Time (s) | Chunk Ratio | Total Chunks |
|------------|---------------|-----------|----------|-------------|--------------|
| 1024       | 256           | 6         | 0.775    | 1:4         | 16           |
| 2048       | 256           | 8         | 1.608    | 1:8         | 64           |
| 4096       | 256           | 10        | 4.648    | 1:16        | 256          |
| 8192       | 128           | 8         | 17.207   | 1:64        | 4096         |

*Chunk Ratio = chunk_size : resolution*

### Observed Patterns

1. **Optimal Chunk Size**: 
   - Stays in **128-256 range** regardless of resolution
   - Formula: `optimal_chunk ≈ 128 to 256` (fixed, not proportional)
   - At 8192, smaller chunks (128) become optimal due to better load balancing

2. **Optimal Process Count**:
   - Scales with resolution up to CPU limit
   - 1024: P=6, 2048: P=8, 4096: P=10, 8192: P=8
   - Pattern: `P ≈ min(CPU_cores, resolution / 1024)`

3. **Scaling Efficiency**:
   ```
   Resolution    Time        Pixels         Scaling Factor
   1024×1024     0.775s      1.35M/s        1.0x (baseline)
   2048×2048     1.608s      2.61M/s        2.1x (quasi-linear)
   4096×4096     4.648s      3.61M/s        6.0x (sub-linear)
   8192×8192     17.21s      3.90M/s        22.2x (diminishing)
   ```

4. **Why Chunk Size Stays Constant**:
   - Trade-off between IPC overhead (favors large chunks) and load balancing (favors small chunks)
   - Mandelbrot has non-uniform workload (boundary pixels take longer)
   - 128-256 is the sweet spot that balances both factors

### Recommended Formula

```python
# Generated by Claude Opus 4.5 on 2026-04-03
def get_optimal_config(resolution, cpu_cores=10):
    """Calculate optimal chunk size and process count for a given resolution."""
    
    # Chunk size: fixed range, use 256 for ≤4096, 128 for larger
    if resolution <= 4096:
        chunk_size = 256
    else:
        chunk_size = 128
    
    # Process count: scale with resolution, cap at CPU cores
    processes = min(cpu_cores, max(6, resolution // 1024))
    
    return chunk_size, processes
```

## 4. Recommendations

### For Single Machine (Multi-core)
1. **Use Dask** for vectorized operations with auto-parallelization
2. **Chunk size = resolution / 4 to 8** (e.g., 512 chunks for 2048+ images)
3. **Process count = CPU cores - 2** to leave headroom for OS

### Optimal Configurations by Use Case

| Use Case | Implementation | Chunk Size | Processes |
|----------|----------------|------------|-----------|
| Quick preview (≤512) | NumPy | N/A | 1 |
| Production (1024+) | Dask | 256-512 | Auto |
| Maximum control | Multiprocess + Numba | 128-256 | 6-8 |
